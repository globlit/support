# Deployment and session foundation

Implemented slice, 2026-11-08. This is a single-owner local/VM foundation, not a hosted or multi-user release.

## Running the existing workspace

`npm run build && npm start` keeps `http://127.0.0.1:4173` and the current data directory. There is no startup token. Open the browser and use the existing Vault passphrase. An unlock authenticates that browser using an HttpOnly, SameSite=Lax cookie and an in-memory CSRF token. The existing routes/filters remain in place, and an expired session hides the mounted UI until the same owner signs in again.

Sessions expire after 12 hours by default and are not persisted across server restart. Signing out revokes this browser session without locking the operational Vault for other browsers. Locking the Vault revokes all sessions and pauses background work under the existing Vault rules. Signing another browser in while the Vault is already unlocked verifies the passphrase without resetting active work or other sessions. The local passphrase represents one workspace owner; it is not four distinct team identities. Google/generic OIDC and hosted role enforcement remain later work.

Notification tokens still authorize only poll/ack operations. Pairing uses an expiring one-use code generated by an authenticated browser. No device token can unlock the Vault or approve work.

| Environment setting | Default | Meaning |
| --- | --- | --- |
| `SUPPORT_DEPLOYMENT` | `local` | `local` or explicitly configured `container`; hosted values fail closed |
| `SUPPORT_PORT` | `4173` | Server listener port, 1024–65535 |
| `SUPPORT_BIND_HOST` | `127.0.0.1` | Local mode requires loopback; container mode can bind the container interface |
| `SUPPORT_PUBLIC_ORIGIN` | Loopback origin for the listener | Exact browser Host/Origin; explicit in container mode, independent of container port |
| `SUPPORT_SESSION_SECONDS` | `43200` | Absolute session expiry; allowed 300–43200 seconds |
| `SUPPORT_DATA_DIR` | `.support-data` | Existing persistent state directory |

Example environment for a future container image: `SUPPORT_DEPLOYMENT=container`, `SUPPORT_BIND_HOST=0.0.0.0`, `SUPPORT_PORT=8080`, `SUPPORT_PUBLIC_ORIGIN=http://127.0.0.1:4173`, with the container port published **only to VM loopback**, `127.0.0.1:4173:8080`. This example configures a listener; it is not a shipped container bundle. Exposure must be checked from another host. Do not use host networking or publish on every VM interface.

This release rejects public/HTTPS origins and proxy-trust options. Forwarded headers never establish user identity or override Host/Origin. Local HTTP cookies do not claim TLS transport security; the remote VM path must be carried over the restricted SSH transport. SameSite=Lax supports the browser's OAuth callback navigation; exact Origin/Fetch-Site checks and CSRF tokens protect mutations. Existing model OAuth state checks remain in place, and a callback now requires a valid browser session.

## Trusted approval identity

The server creates persistent random workspace/owner IDs outside editable application settings. Authenticated request context supplies the actor to plan approvals, MR approval, pipeline fix pushes, ticket creation, resolution/closure, direct replies, intake decisions, ignore rules, alert handoffs and AI dispositions. An edited engineer name or client-supplied identity cannot impersonate an approver.

Identity propagates with AsyncLocalStorage, never a mutable global actor. Approval attribution checks the current session again immediately before recording authority; branch preparation also checks before its external write. Background work does not receive an implicit human identity. Existing fixture tests now supply explicit human contexts, with separate negative tests proving missing/expired/wrong-workspace contexts are denied.

Historical plan approvals without an authenticated actor ID are preserved in `state` under `security.legacy-approval:<connection>:<issue>` but no longer authorize new execution. The current plan returns to review; its versions, comments and history remain. This one-time migration is transactional. Existing completed external effects are not undone or re-executed.

## VM-to-Mac boundary

Support now targets an [existing Vagrant/Tart VM](existing-vm.md); the app-owned VM controller is removed. The host UI gateway and no-direct-tunnel protections remain. Tart/Softnet runtime enforcement still requires Mac validation; installation diagnostics do not authorize a connection.

The next implementation slice replaces the raw TCP forward with a host-owned UI/data gateway and a private Unix-socket SSH forward. The companion now requires host-only proof in VM mode. Host PF generation/verification, independent input snapshots and a no-share Vagrant configuration guard are implemented in [vm-host-boundary.md](vm-host-boundary.md).

That document supersedes the initial tunnel design and lists the provider-specific Mac validation still required. These controls have not been installed on the user's Mac, and an unknown native Vagrant NAT path is not assumed isolated. Local mode and its authenticated sessions remain unchanged.

## Verification and references

Tests cover deployment rejection, anonymous API denial, CSRF, cookie rotation/revocation/expiry, restart/lock behavior, concurrent identity isolation, wrong-workspace denial, approval migration, editable-name impersonation, notification token scope and forbidden tool environment inheritance. The existing workflow suite must continue to pass with explicit authenticated fixture identities.

Validation on 2026-11-08: the production build and all 261 tests passed. Browser checks against an isolated workspace verified Enter-to-unlock, hard-refresh session persistence, sign-out, cross-tab Vault locking, and restoration of the Logs page with its GitLab/error filters. The real workspace was restarted and checked for anonymous API rejection; no real investigation, ticket creation or reply was triggered. Native Mac and guest isolation checks remain outstanding as listed above.
